# Runbook — ระบบคลินิก Offline (สำหรับผู้ดูแล + พนักงาน)

## หน้าผู้ดูแลแบบแยกหมวด (รุ่นพัฒนา 1.0.7 — ยังไม่ใช่ชุดเผยแพร่)

บัญชีผู้ดูแลเข้าสู่หน้า “ดูแลคลินิก” โดยตรง ไม่เข้าหน้าคิวหน้าร้าน ส่วนบัญชีแพทย์และหน้าคลินิกยังเข้าหน้างานเดิม การเปลี่ยนนี้ไม่ได้เพิ่มสิทธิ์รักษาหรือดูรายงานให้ผู้ดูแล

- เลือกหมวด: ข้อมูลคลินิก / เอกสารและการพิมพ์ / ผู้ใช้งาน / เชื่อมต่อเครื่องอื่น / สำรองและกู้ข้อมูล / อัปเดตและเกี่ยวกับโปรแกรม / เครื่องมือขั้นสูง
- ปุ่ม “บันทึก…” บันทึกเฉพาะหมวดที่เปิด; ถ้ามีข้อมูลค้าง ระบบถามก่อนเปลี่ยนหมวดหรือออกจากหน้า
- หมวดผู้ใช้งานกด “เพิ่มผู้ใช้งาน” เพื่อเปิดฟอร์ม; เปลี่ยนรหัสผ่านและ PIN ใช้ปุ่มของแต่ละบัญชี
- สถานะข้อมูลสำรองอยู่เหนือทุกหมวด กด “ดูการสำรองข้อมูล” เพื่อไปจัดการได้
- การอัปโหลดโลโก้และปุ่มดำเนินการเฉพาะ เช่น เพิ่มผู้ใช้ สำรองข้อมูล นำเข้าการตั้งค่า ทำงานเมื่อกดปุ่มนั้น ไม่รอปุ่มบันทึกหมวด
- ถ้าบันทึกแล้วขาดการเชื่อมต่อ ระบบอ่านค่ากลับเพื่อตรวจผล หากยังยืนยันไม่ได้จะคงข้อความแจ้งและข้อมูลที่กรอกไว้ อย่ารีบปิดหน้า

ทดลองด้วยข้อมูลสมมติเท่านั้นก่อนใช้งานจริง; รายละเอียดหลักฐานและข้อจำกัดอยู่ใน `../admin-navigation-handoff.md`

## 1. ติดตั้งครั้งแรก (เครื่องหน้าคลินิก = host)

### วิธีหลัก — ชุดติดตั้งพกพา (ไม่ต้องติดตั้ง Node แยก ไม่ต้องพิมพ์คำสั่ง)

1. บนเครื่องพัฒนา: `cd app && node tools/build-installer.js` → ได้ `dist/ClinicSetup-<version>-<วันที่>.zip` (~35 MB มี Node พกพาในตัว)
   ก่อนส่งมอบทุกครั้ง รัน `node --no-warnings test-installer.js` ต้องผ่าน 8/8
2. ส่ง ZIP ไปเครื่องคลินิก (Google Drive/USB) — ถ้ามาทางเน็ต **คลิกขวา ZIP → Properties → Unblock ก่อนแตกไฟล์** (กันกล่องเตือน SmartScreen)
3. Extract All แล้วดับเบิลคลิก `ติดตั้งระบบคลินิก.cmd` — ตัวติดตั้งจะ: คัดลอกไป `C:\clinic` → สร้างฐานข้อมูลเปล่า (ไม่มี demo) → ถามว่าจะเปิดเองตอนบูตไหม (สร้างทางลัดใน Startup) → สร้างไอคอน "ระบบคลินิก" บนหน้าจอ → เปิดหน้าตั้งค่าครั้งแรก
   ตัวติดตั้ง**ไม่เขียนทับฐานข้อมูลที่มีอยู่แล้วเด็ดขาด** — เจอ `C:\clinic\app\data\clinic.db` เมื่อไรจะหยุดทันที
4. เข้าระบบ `admin`/`admin1234` → **เปลี่ยนรหัสทันที** → ตั้งชื่อคลินิก/ที่อยู่/เลขใบอนุญาต, สร้าง user หมอ+พนักงาน + PIN
5. หน้า **คลังยา**: Import รายการยาจาก CSV แล้วตั้ง "รูปแบบสั่งยาเริ่มต้น" ของยาที่ต้องระบุเวลา เช่น Levodopa
6. กรอกเลขใบประกอบและสาขาของแพทย์ทุกคนก่อนออกใบรับรอง
7. ทำ checklist ส่วน E ในคู่มือหน้าร้านและผู้ดูแลใน docs ของโครงการให้จบ: สำรองข้อมูล + เตรียมรหัสสำรองหรือ Recovery Kit + ซ้อมกู้ — **ครบก่อนใช้เก็บข้อมูลจริง**; ใช้รหัสสำรองแล้วไม่บังคับ USB กู้ฉุกเฉิน

ติดตั้งด้วยตนเองตามคู่มือใน https://github.com/mkungsuki/clinic-offline/tree/main/docs หากติดขัด เปิด GitHub Issue โดยไม่แนบข้อมูลคนไข้ กุญแจกู้ รหัสผ่าน หรือรายงานที่ยังไม่ได้ตรวจข้อมูลส่วนตัว

### วิธีสำรอง — ติดตั้งมือ (สำหรับช่าง)

1. ติดตั้ง **Node.js 24 LTS** (หรือ ≥22.5) จาก nodejs.org — ติดตั้งครั้งเดียว ไม่ต้องมีเน็ตอีก
   ⚠ ระบบใช้ `node:sqlite` ที่ผูกกับเวอร์ชัน Node — **อย่าอัปเกรด Node โดยไม่ทดสอบก่อน**
2. Copy โฟลเดอร์ `app` ทั้งก้อนไปวางที่ `C:\clinic\app` (ไม่ต้อง npm install — zero dependency) — **ห้าม copy `app/data`**
3. ในโฟลเดอร์ app รัน `node --no-warnings seed.js` (ไม่ใส่ `--demo`) แล้ว `node --no-warnings server.js` → เปิด `http://localhost:8080` แล้วตั้งค่าตามข้อ 4-7 ของวิธีหลัก

### ⚠ Checklist ย้ายจากเครื่องพัฒนา → เครื่องคลินิกจริง (ทำครั้งเดียวตอน deploy)

ข้อมูลบนเครื่องพัฒนาเป็นข้อมูลทดลองทั้งหมด **ห้ามยกไปใช้ที่คลินิก**:

1. Copy เฉพาะโฟลเดอร์ `app` — **ห้าม copy `app/data` ไปด้วย** (ข้อมูล+กุญแจทดลอง)
   ชุดติดตั้งจาก `tools/build-installer.js` บังคับข้อนี้ให้อยู่แล้ว (มีทั้ง assertion ตอน build และ test ตรวจซ้ำ)
2. บนเครื่องคลินิก รัน `node --no-warnings seed.js` (ไม่ใส่ `--demo`) → ระบบสร้างฐานข้อมูลเปล่าและกุญแจเข้ารหัสชุดใหม่ของคลินิกเอง — ตัวติดตั้งทำขั้นนี้ให้อัตโนมัติ
3. เปลี่ยนรหัส `admin` ทันที แล้วสร้าง user จริงของหมอ/พนักงาน
4. ตั้ง **รหัสสำรองของคลินิกจริง** จากหน้า "ตั้งค่า" สำรองและซ้อมกู้ด้วยรหัสนี้ หรือเลือกสร้าง Recovery Kit ชุดจริงแทน (รหัส/Kit จากเครื่องพัฒนาใช้กับข้อมูลจริงไม่ได้ — คนละกุญแจ)
5. หากทำ Recovery Kit เพิ่ม USB สำหรับ Kit กับ USB สำหรับเก็บข้อมูลสำรองต้องเป็น **คนละอัน** และเก็บ Kit แยกจากตัวเครื่อง เช่น กลับบ้านไปกับหมอ
6. ไฟล์กุญแจ/ข้อมูลทดลองบนเครื่องพัฒนา ปล่อยไว้ได้ ไม่เกี่ยวกับของจริง

### ตั้งเป็น Windows service (เปิดเครื่องแล้วขึ้นเอง)
1. โหลด NSSM (nssm.cc) วาง `nssm.exe` ไว้ที่ `C:\clinic`
2. PowerShell (Run as Administrator):
   ```
   C:\clinic\nssm.exe install ClinicApp "C:\Program Files\nodejs\node.exe" "--no-warnings C:\clinic\app\server.js"
   C:\clinic\nssm.exe set ClinicApp AppDirectory C:\clinic\app
   C:\clinic\nssm.exe start ClinicApp
   ```
3. เปิด firewall ให้เครื่องห้องตรวจเข้าถึง:
   ```
   netsh advfirewall firewall add rule name="ClinicApp" dir=in action=allow protocol=TCP localport=8080
   ```
4. ตั้ง **IP เครื่อง host ให้คงที่** (เช่น 192.168.1.10) ที่ Network settings หรือ reserve ใน router

### เครื่องห้องตรวจ
- ต่อสาย LAN ถึงกัน (ผ่าน switch/router เดียวกัน ไม่ต้องมีเน็ต)
- เปิด browser ไป `http://192.168.1.10:8080` แล้วทำ shortcut ไว้หน้า desktop
- login ด้วย user หมอ

## 3. Backup & Restore (สำคัญที่สุดในไฟล์นี้)

- ระบบ backup อัตโนมัติทุกคืน (เวลาใน "ตั้งค่า", default 21:00) สร้าง SQLite snapshot, สำรองไฟล์แนบ/โลโก้ และตรวจ SHA-256
- แนะนำอย่างน้อย 3 สำเนา: ในเครื่อง (`app\data\backups\`) + external/เครื่องอีกห้อง + cloud
- ช่อง Cloud รับ path ของโฟลเดอร์ OneDrive/Google Drive ที่ sync อยู่แล้ว ข้อมูลถูกเข้ารหัส AES-256-GCM ก่อน copy
- สถานะ “คัดลอกเข้าโฟลเดอร์ Cloud” **ยังไม่ใช่การยืนยันว่า provider อัปโหลดเสร็จ** ต้องเปิด OneDrive/Drive ตรวจอีกครั้ง
- หน้าตั้งค่า/รายงานจะแสดง “ยังไม่ยืนยันการอัปโหลด” แม้คัดลอกและตรวจไฟล์ในโฟลเดอร์สำเร็จแล้ว การซ้อมกู้จากเครื่องเดิมไม่ใช่การตรวจว่าไฟล์ถึงคลาวด์; ตรวจชุดล่าสุดบนเว็บไซต์ Google Drive/OneDrive ด้วย ป้ายนี้จะไม่หายเองเพราะโปรแกรมยังไม่ได้ตรวจสถานะจากผู้ให้บริการ
- ตั้งรหัสสำรองในหน้า `ตั้งค่า → สำรองและกู้ข้อมูล` ใส่สองครั้งและ PIN ผู้ดูแล แล้วบันทึก/สำรอง ระบบห่อกุญแจเดิมด้วยรหัสและส่ง `clinic-recovery.wrapped.json` ไปทุกปลายทางด้วย กู้บนเครื่องใหม่ใช้โฟลเดอร์ครบชุด + รหัส โดยไม่บังคับ USB
- **Recovery Kit เป็นทางเสริม** ของเดิมยังใช้ได้ เก็บแยกจากเครื่องคลินิกและ USB สำรอง ระบบไม่แสดงหรือดาวน์โหลดกุญแจดิบผ่านหน้าเว็บ รหัสที่พิมพ์ไม่อยู่ในlog/settings/support
- รหัสใช้12–128ตัวอักษร (NFC,ไม่trim) จำ/จด/password managerตามเลือก; เปลี่ยนรหัสขณะเครื่องเดิมยังอยู่ได้ แต่ไม่เพิกถอนenvelopeเก่าที่คนเคยคัดลอก ถ้าลืมรหัส+เสียเครื่อง+ไม่มีKit ผู้พัฒนากู้แทนไม่ได้
- ถ้า ClinicApp รันเป็น NSSM LocalSystem โฟลเดอร์ OneDrive ของ user อาจไม่ sync: ให้ใช้ Scheduled Task ภายใต้บัญชี clinic หรือใช้ปลายทางที่ service เข้าถึงได้ และตรวจในหน้า Reports
- เก็บย้อนหลัง 30 วัน + ไฟล์วันที่ 1 ของทุกเดือนเก็บถาวร **เฉพาะใน `app/data/backups`**; โฟลเดอร์ external/cloud ยังไม่ prune อัตโนมัติ ต้องตรวจพื้นที่ว่าง (งานลบชุดเก่าปลายทางยังเป็น backlog)
- **ซ้อมกู้ข้อมูลก่อนเปิดคลินิกจริง 1 ครั้ง และทุก 6 เดือน** — backup ที่ไม่เคยลองกู้ = ไม่มี backup

### วิธีทดสอบ Backup หลังตั้งค่า

1. หน้า `ตั้งค่า` กด **สำรองข้อมูลตอนนี้** แล้วตรวจผลแยกแต่ละปลายทาง ไม่ใช้สีเขียวเป็นหลักฐานอัปโหลด
2. โฟลเดอร์ปลายทาง (external/Cloud) ต้องมีไฟล์ timestamp เดียวกันครบอย่างน้อย `clinic-*.db.enc` และ `clinic-*.manifest.json.enc` รวมทั้งโฟลเดอร์ `attachments` / `assets` — ข้อมูลที่ออกนอกเครื่องถูกเข้ารหัสทั้งหมด
3. ต้องไม่มีชื่อ `.partial-*` ค้าง; ถ้ามีหรือไม่มี manifest ให้ถือว่ารอบนั้นยังไม่สมบูรณ์
4. เปิด Google Drive/OneDrive บนเว็บและตรวจว่าไฟล์ timestamp ล่าสุดมองเห็นจาก provider แล้ว
5. ตรวจว่าไฟล์สำหรับรหัสล่าสุดส่งครบด้วย แล้วกดซ้อมกู้และใส่รหัส; โหมดนี้ไม่ใช้keyในเครื่องช่วย. หากเลือกใช้Kitแทนให้ตรวจว่าKitยังอยู่และเปิดได้

### กู้ด้วยรหัสบนเครื่องใหม่ (ไม่ต้องมี USB กู้ฉุกเฉิน)

ติดตั้งโปรแกรม → ดาวน์โหลดโฟลเดอร์สำรองครบจากบัญชีคลาวด์หรือเลือกUSBสำรอง → เปิดไอคอน **กู้ข้อมูลคลินิก** → เลือกโฟลเดอร์ → ใส่รหัสสำรอง → ตรวจวันที่และซ้อมกู้ → ยืนยันกู้จริง. ข้อมูลหลังวันสำรองไม่อยู่ในชุดนั้น. ตัวช่วยนำkey/envelopeกลับเข้าเครื่องใหม่เพื่อให้สำรองต่อได้; ตรวจและตั้งปลายทางให้ตรงเครื่องใหม่ด้วย

หากขาดการติดต่อหลังpublish ตัวช่วยแสดง **ตรวจผลการกู้ครั้งก่อน** และตรวจการเปิดโปรแกรมต่อโดยไม่publishซ้ำ; op_idสำเร็จแล้วretryไม่ทับงานใหม่. Bootกู้journalที่ขาดช่วงก่อนเปิดDB. เครื่องเก่าเห็นwriterรุ่นใหม่ในปลายทางร่วมต้องหยุดcopy; ถ้าcloudยังไม่syncmarkerหรือเป็นโฟลเดอร์ดาวน์โหลดคนละที่ ตรวจไม่ได้ จึงให้หยุดใช้เครื่องเก่า ไม่อ้างdistributed lock

### วิธีซ้อมกู้ / กู้ข้อมูลจริงด้วย Recovery Kit (ทางเสริม)

ทางปกติสำหรับเจ้าของคลินิก ไม่ต้องพิมพ์คำสั่งใดๆ:

1. เสียบ USB **Recovery Kit** เข้ากับเครื่อง
2. ดับเบิลคลิก **"เปิดตัวช่วยกู้ข้อมูล"** ในไดรฟ์ USB — เบราว์เซอร์จะเปิดหน้าตัวช่วยขึ้นมาเอง
3. ตัวช่วยจะค้นหาข้อมูลสำรองให้ แนะนำชุดล่าสุดที่เข้ารหัสถูกต้อง แล้วให้กด **"ซ้อมกู้ข้อมูล"** ก่อนเสมอ — ขั้นนี้แค่ตรวจว่าข้อมูลเปิดได้จริง **ไม่แตะข้อมูลที่ใช้งานอยู่**
4. ถ้าจำเป็นต้องกู้จริง (ClinicApp เปิดไม่ได้/ข้อมูลเสีย) ให้กด **"กู้ข้อมูลจริง"** แล้วพิมพ์เลขยืนยัน 4 หลักตามที่ระบบแสดง — ระบบจะสำรองข้อมูลเดิมไว้อีกชั้น กู้ ตรวจ แล้วเปิดใหม่ให้ ถ้าเปิดไม่สำเร็จจะย้อนข้อมูลเดิมกลับให้อัตโนมัติ

### กู้ด้วยคำสั่ง (สำหรับช่างเท่านั้น — ทางสำรอง)

ใช้เมื่อไม่มีตัวช่วยหรือต้องตรวจบนเครื่องอื่น (ไฟล์กุญแจคือ `Recovery Key.txt` ในโฟลเดอร์ Recovery Kit):

1. Copy โฟลเดอร์ cloud/external backup และไฟล์ `Recovery Key.txt` จาก Recovery Kit มายังเครื่องสำรอง
2. รันคำสั่ง โดย output ต้องเป็นโฟลเดอร์ใหม่ที่ยังไม่มี:
   ```
   node tools\restore-cloud-backup.js "D:\Cloud Clinic Backup" "E:\Clinic Recovery Kit\Recovery Key.txt" "C:\clinic-restore-check"
   ```
3. ต้องเห็น `RESTORE-VERIFIED.txt` แล้วเปิดตรวจ `C:\clinic-restore-check\data` ก่อน
4. หยุด ClinicApp จากนั้นจึงใช้โฟลเดอร์ `data` ที่ตรวจแล้วแทนของจริง ห้าม restore ทับขณะระบบกำลังรัน

## 4. Troubleshooting

| อาการ | แก้ |
|---|---|
| เข้าระบบไม่ได้ทั้งสองเครื่อง | เครื่อง host: restart service → `C:\clinic\nssm.exe restart ClinicApp` หรือ restart เครื่อง (ขึ้นเองใน <1 นาที) |
| เครื่องห้องตรวจเข้าไม่ได้ แต่ host ใช้ได้ | เช็คสาย LAN, ping 192.168.1.10, เช็ค firewall rule ตามข้อ 1 |
| ขึ้นแถบแดง "นาฬิกาเครื่องนี้ย้อนหลัง..." | นาฬิกาเครื่อง host ผิด (มักเป็นถ่าน CMOS) — ตั้งเวลาให้ถูกใน Windows Settings > Time แล้ว restart service ระบบจะกลับมารับข้อมูลเอง |
| ยาติดลบ / ขึ้น "นับสต็อก" | ขายได้ตามปกติ — พอว่างให้นับจริงแล้วกด "ปรับยอด" พร้อมเหตุผล |
| ลืมรหัสผ่าน | admin ตั้งใหม่ได้ที่หน้า "ตั้งค่า"; ถ้าลืมรหัส admin เอง → ติดต่อผู้พัฒนา (แก้ผ่าน DB ได้) |
| อยากย้ายไประบบอื่น | หน้า "รายงาน" → Export CSV ทุกตาราง — ข้อมูลทั้งหมดออกได้ตลอด ไม่ผูกติดระบบนี้ |
| Cloud ขึ้นว่าไฟล์ไม่สมบูรณ์ | รอ Drive sync แล้วกดทดสอบใหม่; รุ่นปัจจุบัน retry การอ่าน virtual drive สูงสุด 7.9 วินาที ถ้ายังแดงให้ตรวจพื้นที่ว่าง/สิทธิ์ path และต้องมีทั้ง DB + manifest ก่อนถือว่าสำเร็จ |

## รายงานบริหารยารายเดือน (รุ่นพัฒนา 1.0.7)

หน้า **รายงาน → บริหารยารายเดือน** เลือกเดือนและเรียงตามจำนวนตามบิล/ส่วนต่าง/ชื่อยาได้ ไม่ต้องกรอกข้อมูลใหม่

- ยอดตามเดือนออกใบ นับเฉพาะใบที่ยังไม่ยกเลิก ณ ตอนเปิดรายงาน ไม่ใช่สมุดปิดงวดหรือเงินสดสุทธิ รายงานย้อนหลังจึงเปลี่ยนได้เมื่อยกเลิกบิลภายหลัง
- ส่วนลดทั้งบิลถูกแบ่งให้ยาและบริการตามสัดส่วนราคา เศษสตางค์จัดให้ยอดรวมตรงกัน เป็นค่าประมาณเพื่อบริหาร ไม่แก้รายการในใบเสร็จ
- ทุนเป็นราคาที่บันทึกไว้ตอนออกใบ ไม่ใช่ทุนรายล็อตจริง; “ส่วนต่าง” ยังไม่หักค่าแรง/ค่าเช่า/ยาสูญเสีย และไม่ใช่ยอดยื่นภาษี
- “ข้อมูลต้นทุนไม่ครบ”: บิลเก่าไม่มีทุน จึงไม่เดาทุนศูนย์หรือใช้ทุนวันนี้ย้อนหลัง ตั้งทุนในหน้าคลังยาจะมีผลกับบิลใหม่เท่านั้น
- “มีแก้บิล/ยกเลิก/คืนเงิน ต้องตรวจ”: งดแสดงทุนและส่วนต่างของยาที่เกี่ยวข้อง ให้ตรวจใบเสร็จและการคืนของจริงจากรายงานรายวัน ไม่เดาเงินคืนจากเหตุผลยกเลิก
- คงเหลือและวันหมดอายุเป็น **ปัจจุบัน** ไม่ใช่สิ้นเดือนที่เลือก วันหมดอายุคือล็อตที่ยังไม่ปิด ต้องตรวจของในตู้ ระบบยังไม่ได้ตัดจำนวนแยกล็อต; “เทียบหน่วยไม่ได้” หมายถึงรายการเก่ามีหน่วยต่างจากปัจจุบันหรือไม่มีรหัสอ้างอิง
- โหลดไม่สำเร็จจะแสดงข้อความค้างไว้พร้อมปุ่ม “โหลดใหม่” การเปิด/โหลดซ้ำไม่ออกบิลและไม่ขยับสต็อก

ตารางยารายวันเดิมแสดงส่วนต่างก่อนส่วนลดบิล ส่วนรายเดือนใหม่จัดสรรส่วนลดแล้ว จึงไม่ควรเทียบข้ามรายงานโดยไม่ดูฐานคำนวณ เมื่อข้อมูลทุนขาด ทั้งรายวัน/รายเดือน/ยอดรวมปีจะงดแสดงกำไรบนจอ สูตรยอดรายรับเดิมไม่เปลี่ยน

## 6. กระดาษคือ fallback เสมอ

### ใบยาอ่านง่าย (รุ่นพัฒนา 1.0.7)

ปิดไว้ก่อน ผู้ดูแลเปิดได้ที่ ตั้งค่า → กระดาษและการพิมพ์ → ใบยาอ่านง่าย แล้วกดบันทึก
จากใบเสร็จที่มีรายการยา กด “เปิดใบยาอ่านง่าย” เลือก A4/A5 และ 18/20/24 pt ได้ก่อนกดพิมพ์ (เริ่ม A4/20 pt) ไม่พิมพ์เองอัตโนมัติ
เลือก “แบบภาพและข้อความ” จะเห็นภาพช่วงเวลาและจำนวนยาจากคำสั่งที่หมอเลือกไว้เดิม ไม่ต้องกรอกใหม่; เลือก “แบบข้อความ” ได้เฉพาะใบนี้ ภาพเป็นดำบนขาวและมีคำกำกับ ไม่ต้องมีเครื่องพิมพ์สี
ถ้าหมอพิมพ์วิธีใช้เอง เป็นข้อมูลเก่า หรือคำสั่งที่บันทึกไว้จับคู่กับบิลไม่ได้ จะขึ้น “อ่านตามข้อความ” นี่คือการคงคำสั่งเดิม ไม่ใช่ให้เติมเวลาเอง ส่วนยาที่ระบุเวลาเฉพาะ/เมื่อมีอาการ จะใช้รูปแบบของคำสั่งนั้น ไม่เปลี่ยนเป็นเช้าเย็น
การ์ดภาพจะอยู่ครบหน้า หากรายการยาวจนไม่พอแม้เริ่มหน้าใหม่ ระบบใช้ข้อความเต็มพร้อมป้าย “รายการนี้ยาวเกินแบบภาพ”; ลอง A4 ได้ ชื่อยา/วิธีใช้/จำนวนและชื่อผู้ป่วยไม่เล็กกว่า 18 pt ส่วนวันที่/เลขอ้างอิง/เลขหน้า 12 pt
ตั้ง printer ให้กระดาษตรงและขนาดจริง 100% ไม่ใช้พอดีหน้า ตัวใหญ่หรือข้อความยาวขึ้นหน้าใหม่ ไม่ย่อให้เล็กลง ชื่อคนไข้/ชื่อยาต่อเนื่องและเลขหน้าต้องครบก่อนส่งมอบ
ใช้วิธีใช้ที่บันทึกตอนจ่ายยา ไม่ดึงจากคลังใหม่ ไม่เดาวิธีใช้ที่ขาด หากบิลถูกยกเลิก/ขาดวิธีใช้ ระบบจะไม่ออกใบยา ให้กลับตรวจเอกสารของครั้งที่ตรวจและแก้ตามขั้นตอนเดิม
การเปิด/พิมพ์ซ้ำไม่สั่งยาและไม่ตัดสต็อก เหมาะเป็นใบเสริม ไม่ใช่รายการยาทั้งหมดที่คนไข้ใช้อยู่ ต้องลองอ่านกับผู้สูงอายุ/ผู้ดูแลจริง

ถ้าระบบล่มกลางวัน: ใช้บัตร OPD กระดาษต่อได้ทันที แล้วค่อยคีย์ย้อนหลังตอนระบบกลับมา —
ระบบออกแบบให้ "หายไปได้โดยคลินิกไม่ตาย" (brief §9)

## เริ่มฝึกใหม่ / ถอนชุดทดลอง (ตั้งแต่ 1.0.11)

ที่เครื่องหลัก เข้าด้วยบัญชีผู้ดูแล → ตั้งค่า → อัปเดตและเกี่ยวกับโปรแกรม → **จัดการชุดทดลอง**

- **เริ่มฝึกใหม่**: ลบข้อมูลฝึก บัญชี การตั้งค่า และสำเนาภายในชุดทดลอง แล้วสร้างข้อมูลตัวอย่างเหมือนติดตั้งใหม่ โปรแกรมและการเชื่อมเครื่องหมอยังอยู่ เมื่อเสร็จปิดแท็บเก่าและเปิดไอคอนทดลองใหม่ เข้าด้วย `admin / admin1234`, `doctor / doctor123` หรือ `front / front123`
- **ถอนชุดทดลองและข้อมูลฝึกทั้งหมด**: ถอนโปรแกรมทดลอง ข้อมูลและสำเนาภายในชุด ทางลัดที่ชี้ชุดนี้ กฎเชื่อมต่อทดลอง และใบรับรองสาธารณะของชุดนี้ที่นำเข้าบนเครื่องนี้ โฟลเดอร์ส่งหมอบน Desktop จะลบเฉพาะที่พิสูจน์ว่าเป็นของชุดนี้และไม่มีไฟล์อื่นปน

อ่านกล่อง Windows ก่อนยืนยัน ค่าเริ่มต้นคือ **ไม่ใช่** หากเคยใส่ข้อมูลจริงหรือต้องเก็บงานให้ยกเลิกและปรึกษาผู้ดูแลก่อน ทั้งสองคำสั่งไม่ย้ายข้อมูลไปตัวจริง ไม่ลบไฟล์ ZIP ที่ดาวน์โหลด สำเนาที่ส่งออกไป USB/คลาวด์ โฟลเดอร์ที่ย้าย/เพิ่มไฟล์เอง หรือไฟล์/ใบรับรองบนคอมอีกเครื่อง

ระหว่างทำงานให้ทุกเครื่องหยุดใช้เดโม รอ **กล่องแจ้งผล** หากงานค้างให้เปิด `ทำต่อ.cmd` ในโฟลเดอร์ผลที่หน้าเว็บบอก (`%LOCALAPPDATA%\ClinicOffline\TrialMaintenance\<รหัสรอบ>`); มี `ผลการจัดการ.txt` และ `การทำงาน.log` โดยไม่เก็บข้อมูลฝึกหรือกุญแจไว้ในโฟลเดอร์นี้ กดทำต่อเป็นงานเดิม ไม่สร้างรอบลบใหม่ หากยังเข้าเว็บได้กด “เปิดตัวช่วยงานเดิมอีกครั้ง” ได้ด้วย

ถ้าจะอัดเฉพาะบทเปิดคลิปใหม่ ไม่จำเป็นต้องลงโปรแกรมใหม่ ใช้ “เริ่มฝึกใหม่” เมื่ออยากได้สถานการณ์ฝึกตั้งต้น; ใช้ “ถอนชุดทดลอง” เมื่อต้องการสาธิตติดตั้งตั้งแต่เครื่องยังไม่มีเดโม
